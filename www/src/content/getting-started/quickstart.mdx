# Quickstart

This guide will help set up a simple MAF application (both server and client)
that synchronizes a counter between multiple clients.

⚠️ **NOTE**: MAF is still in very early development: things are not easy to do,
APIs and features are subject to change, and things will break!

## Recommended File Structure

MAF is a full-stack framework, helping you build both server and client code.
This guide guides you through setting up a project with **both** server and
client code, so it is recommended to use the following file structure:

```
project-root/
|-- server/             # Your server code
|--   ...               # ... other server files (with your code)
|-- client/             # Your client code
|--   ...               # ... other client files (with your code)
```

Sometimes, you may want to use a different file structure, such as having
pre-made server code and you want to add client code to it, or vice versa.
Decide what works best for you, but keep in mind that the guide will assume
the above structure.

## Install MAF CLI

MAF CLI is a command-line tool that helps you run, test, and deploy MAF servers.

<Tabs defaultValue="macos-linux">
  <TabsList>
    <TabsTrigger value="macos-linux">MacOS/Linux</TabsTrigger>
  </TabsList>

<TabsContent value="macos-linux">

You will need to have [Git](https://git-scm.com/) and a Rust toolchain installed
to build MAF CLI from Scratch. See [https://www.rust-lang.org/tools/install](https://www.rust-lang.org/tools/install)
for Rust installation instructions.

To install MAF CLI, run the following commands in your terminal:

```bash
# While in the root of your project directory,
$ cd /tmp # or any other temporary directory
$ git clone https://github.com/giilbert/maf.git
$ cd maf/crates/maf_cli
$ cargo install --path .
```

If the installation is successful, you should be able to run the `maf_cli`
command:

```bash
$ maf_cli -V
maf_cli 0.1.0
```

Add the following to your shell configuration file (e.g., `~/.bashrc`,
`~/.zshrc`):

```bash
alias maf="maf_cli"
```

This will allow you to run the `maf` command instead of `maf_cli`. The rest of
the documentation will refer to the `maf` command.

## Write a MAF Server

<Tabs defaultValue="rust">
  <TabsList>
    <TabsTrigger value="rust">Rust</TabsTrigger>
  </TabsList>

<TabsContent value="rust">

1\. Create a new Rust project use Cargo:

```bash
$ cargo --lib new server # MAF applications compile as Rust libraries
$ cd server
```

2\. Create a `maf-project.toml` file in the `server` directory with the
following content:

```toml
name = "your-project-name" # Edit this to your application name
rooms = "AutoCreate" # This will make MAF put all users in a single room

# If your build output path is different, adjust the paths accordingly.
[debug]
command = "cargo build --target wasm32-wasip2"
output = "./target/wasm32-wasip2/debug/server.wasm"

[release]
command = "cargo build --target wasm32-wasip2 --release"
output = "./target/wasm32-wasip2/release/server.wasm"
```

3\. Add the following to the `Cargo.toml` file:

```toml
[dependencies]
# Adds maf as a Git repository dependency
maf = { repository = "https://github.com/giilbert/maf" }
# serde is a library for serializing and deserializing data
serde = { version = "^1", features = ["derive"] }

[lib]
crate-type = ["cdylib"] # This is required for Cargo to build the library
```

4\. Edit the `src/lib.rs` file to include the following code:

```rust
use maf::*;

struct CounterStore;

impl StoreData for CounterStore {
    type Data = i32;

    fn init() -> Self::Data {
        0
    }

    // Determines what data to send to the client when the store is serialized
    fn select(data: &Self::Data, _user: &User) -> impl serde::Serialize {
        data
    }

    // This name will be used to identify the store
    fn name() -> impl AsRef<str> {
        "count"
    }
}

// RPC functions can be used to perform actions on the server
async fn increment_counter(
    // Special types for extracting parameters, data, and context
    Params(counter): Params<i32>,
    test: Store<CounterStore>
) -> i32 {
    let mut data = test.write().await;
    *data += counter;
    println!("incremented counter by {counter}. new value: {}", &*data);
    *data
}

async fn on_connect(user: User) {
    println!("user connected! id: {}", user.meta.id());
}

// Declare what the MAF application should do
fn build() -> App {
    App::builder()
        .on_connect(on_connect)
        .rpc("increment_counter", increment_counter)
        .build()
}

maf::register!(build);

```

## Use a MAF Client

The client library allows you to connect to a MAF server and interact with it.

<Tabs defaultValue="javascript-typescript">
  <TabsList>
    <TabsTrigger value="javascript-typescript">JavaScript/TypeScript</TabsTrigger>
  </TabsList>

<TabsContent value="javascript-typescript">

This guide will begin with you creating a new directory for your client code
and initializing a npm package in that directory (e.g. `npm init -y` or
equivalent).

Currently, the package should be installed using the workspace feature of your
package manager. This allows you to link directories as packages in your code.

Refer to the documentation of your package manager for more information on
workspaces:

- **npm**: [https://docs.npmjs.com/cli/v8/using-npm/workspaces](https://docs.npmjs.com/cli/v8/using-npm/workspaces)
- **Yarn (v4)**: [https://yarnpkg.com/features/workspaces](https://yarnpkg.com/features/workspaces)
- **pnpm**: [https://pnpm.io/workspaces](https://pnpm.io/workspaces)
- **Bun**: [https://bun.sh/docs/install/workspaces](https://bun.sh/docs/install/workspaces)

1\. Add `maf/packages/client` as a workspace and `@maf/client` as a dependency
in your `package.json`.

Using pnpm, you can do this by creating a `pnpm-workspace.yaml` file in the
client directory with the following content:

```yaml
packages:
  # Adjust the path if you installed MAF in a different directory
  - ../maf/packages/client
```

... adding the following to your `package.json`:

```json
{
  "name": "your-client-name",
  "version": "0.1.0",
  "dependencies": {
    "@maf/client": "workspace:*"
  }
}
```

and running `pnpm install` in the client directory.

2\. Install additional dependencies to build/run your code. If you're building
a website, you will need a bundler like [Vite](https://vite.dev/),
[Parcel](https://parceljs.org/), or [Webpack](https://webpack.js.org/).

3\. Write the following code:

```typescript
import { MafClient } from "@maf/client";

const client = new MafClient({
  url: "http://localhost:3000",
  // Use the same name as in `maf-project.toml`
  app: "your-organization/your-project-name",
});

// Use the same name as in `StoreData`
const store = client.store("counter");

store.on("change", (data) => {
  console.log("Counter value changed:", data);
});

async function run() {
  await client.connect();

  console.log("Connected to the server!");

  // Call the RPC function to increment the counter every second
  while (true) {
    const _result = await client.rpc<number>("increment_counter", 1);
    await new Promise((resolve) => setTimeout(resolve, 1000));
  }
}

run();
```
